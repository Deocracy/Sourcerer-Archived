  <action>
    PolyForm Noncommercial 1.0.0 is NOT a registered SPDX identifier. Do not invent one
    (`PolyForm-Noncommercial-1.0.0`, `LicenseRef-PolyForm-NC`, or similar) in either manifest —
    each ecosystem has a documented escape hatch and they are different from each other.

    In `package.json`: add a top-level `"license": "SEE LICENSE IN LICENSE"` key. That exact
    string is npm's own documented convention for a license whose text lives in a repo file
    rather than in the SPDX list. Place it adjacent to the existing `"private": true` key,
    matching the file's existing flat top-level key ordering. Do not reorder or reformat any
    other key, and do not touch the `scripts` block.

    In `src-tauri/Cargo.toml`: add `license-file = "../LICENSE"` to the existing `[package]`
    block (the path is relative to the manifest, and `LICENSE` lives one directory up at the
    repo root). Use `license-file`, NOT `license` — Cargo's `license` field validates as an
    SPDX expression and would reject or misrepresent a PolyForm identifier. Do not add both
    keys; Cargo treats `license` and `license-file` as alternatives. Do not touch the
    `[dependencies]` block or any other section.

    Neither edit changes application behavior; both files must remain valid (`package.json`
    parseable as JSON, `Cargo.toml` parseable as TOML).
  </action>
  <verify>
