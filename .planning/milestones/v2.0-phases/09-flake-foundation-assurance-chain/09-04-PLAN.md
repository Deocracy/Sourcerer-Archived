  <name>Task 2: Write the cross-platform toolchain drift gate</name>
  <files>scripts/drift-gate.mjs</files>
  <read_first>
    - scripts/verify-fonts.mjs (the established convention this script must match: ESM, `node:`-prefixed core imports, labeled `console.error` + `process.exit(1)` on failure, plain `console.log` PASS summary, zero external dependencies)

  </read_first>
  <action>
    Create `scripts/drift-gate.mjs`, a zero-dependency ESM Node script that fails when the
    toolchain resolved in the *current environment* diverges from the repo's pin files. It runs
    identically on `windows-latest` and inside `nix develop` on Linux — that is why it is a Node
    script and not inline shell. Follow `scripts/verify-fonts.mjs`'s conventions exactly: `node:`
    core imports only, every message prefixed `drift-gate — `, `console.error` +
    `process.exit(1)` on failure, `console.log` PASS summary on success.

    Behavior:
    - Read `rust-toolchain.toml` from the repo root and extract the `channel` value from the
      `[toolchain]` table. Do not add a TOML parser dependency — a targeted regex over the
      `channel = "..."` line is sufficient and matches the "no new dependency for a few lines"
      rule. If the channel is a floating name (`stable`, `beta`, `nightly`), fail immediately
      with a message saying the pin must be an exact version, since a floating channel makes this
      gate unfalsifiable.
    - Read `.nvmrc` and trim whitespace.
    - Shell out with `node:child_process` `execFileSync` to `rustc --version` and read
      `process.version` for Node (no subprocess needed for Node — the running interpreter is the
      resolved Node). Strip the leading `v` from `process.version`.
    - Compare: the resolved `rustc` version must equal the pinned channel exactly, and the
      resolved Node version must equal `.nvmrc` exactly. Use exact equality, not a prefix match —
      the pins are exact versions, so a prefix match would silently accept `1.97.10` for a
      `1.97.1` pin.
    - On any mismatch, print both the expected and the actual value for each failing tool, then
      exit 1. On success print one line naming both matched versions.
    - Handle `rustc` being absent as a failure with a clear message (it means the Windows job's
      rustup never resolved `rust-toolchain.toml`, which is exactly Pitfall 4).
    - Resolve file paths relative to the repo root derived from `import.meta.url`, not from
      `process.cwd()`, so the script works regardless of the working directory CI invokes it from.

    Do NOT make the script install or modify anything. It only observes and compares — the whole
    point is that it is an independent judge of whatever the job's setup steps produced.
  </action>
  <verify>
    <automated>bash -c '
set -euo pipefail
nix develop --command node scripts/drift-gate.mjs
# negative test: a mutated pin must make the gate fail
cp rust-toolchain.toml /tmp/rt.bak
sed -i "s/1\.97\.1/1.70.0/" rust-toolchain.toml
if nix develop --command node scripts/drift-gate.mjs; then cp /tmp/rt.bak rust-toolchain.toml; echo "FAIL: gate passed on a drifted pin"; exit 1; fi
cp /tmp/rt.bak rust-toolchain.toml
nix develop --command node scripts/drift-gate.mjs
git diff --quiet rust-toolchain.toml
echo "drift gate OK (passes clean, fails on drift, restored)"
'</automated>
  </verify>
  <acceptance_criteria>
    - `node scripts/drift-gate.mjs` run inside `nix develop` exits 0 and prints a PASS line naming the matched Rust and Node versions.
    - With `rust-toolchain.toml`'s channel temporarily altered, the same command exits non-zero and prints both the expected and actual Rust version.
    - After restoring the file, `git diff --quiet rust-toolchain.toml` succeeds (the negative test left no residue).
    - The script imports nothing outside `node:` core modules (`grep -c "^import" scripts/drift-gate.mjs` shows only `node:`-prefixed specifiers).
    - Every failure message begins with `drift-gate — `.
    - The script exits non-zero when `rust-toolchain.toml`'s channel is `stable`, `beta`, or `nightly`.
    - The script resolves its file paths from `import.meta.url`, not `process.cwd()`.
  </acceptance_criteria>
