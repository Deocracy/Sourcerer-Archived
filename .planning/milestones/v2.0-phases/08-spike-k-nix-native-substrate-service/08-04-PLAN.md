<objective>
Prove the exemption set in the form Phase 15's compiler will actually emit — a declarative
`systemd.services.coolwsd.serviceConfig` attrset in `configuration.nix`, applied by
`nixos-rebuild switch` with the exploratory drop-in deleted first — and prove the Collabora UI
is reachable on 127.0.0.1 from the Windows host by both curl and browser (D-13).

Purpose: the ladder found the exemption set with drop-ins because drop-ins iterate in seconds
where a rebuild costs ~109 s. But a drop-in is not what the platform will ship. RESEARCH Pitfall
4 is that a stale drop-in survives `nixos-rebuild switch` and silently shadows the declarative
config, so the "final proof" can be a measurement of the thing it was supposed to replace. The
teardown before the rebuild is therefore load-bearing, not hygiene.

Output: `leg_declarative` filled into `run.sh`, executed, with `DECLARATIVE_MATCH`, the
re-asserted four signals, and the Windows-side reachability result recorded in `run.log`.
</objective>

<interfaces>
Declarative rendering target — the Nix form the exemption set must be expressed in. Option path
verified against nixpkgs source; `systemd.services.<name>.serviceConfig` is a freeform attrset,
so any systemd directive name is accepted, and Nix booleans render as `yes`/`no`, lists render
as space-separated values:

  systemd.services.coolwsd.serviceConfig = {
    DynamicUser           = true;                       # bool  -> yes/no
    ProtectSystem         = "strict";                   # string
    CapabilityBoundingSet = [ ];                        # list  -> empty
    RestrictNamespaces    = [ "~cgroup" "net" "pid" "ipc" "uts" ];
    SystemCallFilter      = [ "@system-service" "@mount" "unshare" "setns" "clone3" "pivot_root" ];
    ...                                                 # one entry per EXEMPTION_SET pair
  };

Rendering rules the generator must follow:
  - `Key=` with an empty value  -> `Key = [ ];`   (empty list, e.g. CapabilityBoundingSet)
  - `Key=yes` / `Key=no`        -> `Key = true;` / `Key = false;`
  - values containing spaces    -> a Nix LIST of quoted words, not one quoted string with
                                   spaces; systemd treats these as multiple values and a single
                                   quoted string would be a different, wrong unit
  - everything else             -> `Key = "value";`
  - `User=` (the empty reset)   -> omit entirely when DynamicUser is true; emit `User = "cool";`
                                   when DynamicUser was relaxed to false

If rung 4a passed (socket activation), the declarative form additionally needs
`systemd.sockets.coolwsd = { listenStreams = [ "127.0.0.1:9980" ]; wantedBy = [ "sockets.target" ]; };`
and `Sockets = [ "coolwsd.socket" ];` in the serviceConfig. If 4b was the concession instead,
render `PrivateNetwork = false;` with `IPAddressDeny = "any";` and `IPAddressAllow = "localhost";`.

run.log key=value lines this plan writes (plan 05 greps for these):
  DECLARATIVE_REBUILD_SECONDS=<n>
  DECLARATIVE_MATCH=yes|no
  DECLARATIVE_ACTIVE=<systemctl is-active result>
  DECLARATIVE_JAIL=ok|degraded|unknown
  DECLARATIVE_REACH_GUEST=ok|fail
  WINDOWS_REACH=ok|fail
  WINDOWS_REACH_CAUSE=hardening|wsl-forwarding|n/a
  DISTRO_FINAL_STATE=registered
</interfaces>

  <action>
Replace the `leg_declarative` stub in `run.sh`.

Step 1 — read the input. Grep `EXEMPTION_SET=` out of `$LOG` (last occurrence wins, so a
resumed ladder's final value is used). Abort this leg with a clear message if it is missing or
empty; without it there is nothing to prove and silently rebuilding stock Collabora would be a
false green.

Step 2 — tear down the drop-in, before anything else touches the guest:
`rm -rf /etc/systemd/system/coolwsd.service.d` and, if rung 4a created it,
`rm -f /etc/systemd/system/coolwsd.socket`, then `systemctl daemon-reload`. This is RESEARCH
Pitfall 4: `nixos-rebuild switch` does not clear `/etc/systemd/system/*.d/` because the module
does not manage that path, so a surviving drop-in would shadow the declarative config and the
"final proof" would be measuring the drop-in again. Immediately verify the teardown with
`test ! -d /etc/systemd/system/coolwsd.service.d` and log the result — do not assume `rm -rf`
succeeded.

Step 3 — render the Nix attrset. Convert each `Directive=Value` pair from `EXEMPTION_SET`
using the rendering rules in `<interfaces>`. Emit the rendered block to `$LOG` before writing
it, so the trail shows exactly what was generated and plan 05 can quote it as the README's
declarative excerpt. Pay particular attention to the space-containing values
(`RestrictNamespaces`, `SystemCallFilter`, `CapabilityBoundingSet`): they must become Nix lists
of quoted words, because a single quoted string with embedded spaces is a semantically
different, wrong unit.

Step 4 — write it into the guest's `/etc/nixos/configuration.nix` through `guest_root` using
the 010 sed-insert-before-final-brace pattern, guarded for idempotency by grepping for
`systemd.services.coolwsd.serviceConfig` first. Because the block is multi-line, write it to a
temp file inside the guest and splice it in rather than trying to sed a multi-line literal — a
multi-line sed insert through the `wsl.exe` + MSYS + `sh -c` layers is exactly the kind of
quoting that silently corrupts. `cat` the resulting config tail into `$LOG` afterwards.

Step 5 — timed `nixos-rebuild switch` through `guest_root`, using 010's
`T0=$SECONDS ... rc=$? ... echo "..._seconds=$((SECONDS-T0)) rc=$rc"` shape. Log as
`DECLARATIVE_REBUILD_SECONDS=`. A rebuild failure here is a real finding (the drop-in form and
the module-override form are not equivalent) — log the full error and continue rather than
aborting the leg, because plan 05 must record it.

Step 6 — prove the declarative config is what actually took effect. Run `systemctl show coolwsd`
with an explicit `-p` for every directive in `EXEMPTION_SET`, plus `-p DropInPaths`. Assert two
things and log `DECLARATIVE_MATCH=yes|no` with the diff on mismatch:
  (a) `DropInPaths` is empty or contains no `coolwsd.service.d` entry — proving no stale drop-in
  (b) every directive's live value equals the exemption-set value it was rendered from
Note that systemd normalises some values on readback (`CapabilityBoundingSet=` shows as an empty
string, `RestrictNamespaces=~...` may print as the complement set, booleans as `yes`/`no`) —
compare semantically and record the raw readback verbatim so a later reader can judge for
themselves.

Step 7 — re-assert the four signals against the declarative unit, exactly as the ladder did.
Do not carry them over from the ladder; the whole point is that the declarative path is proven
independently. Log `DECLARATIVE_ACTIVE=`, `DECLARATIVE_JAIL=` (via `jail_state` over the window
since the rebuild), and `DECLARATIVE_REACH_GUEST=` (via `reach_state`).

Step 8 — also run `systemd-analyze security coolwsd.service --no-pager` through `guest_root`
and log the full per-directive breakdown plus the overall exposure score. This is the exact
tool Phase 19's audit gate uses, so capturing the number this exemption set scores is what makes
Phase 19 plannable. Record it as evidence only — do not gate on the score, and note in the log
that the score reflects DECLARED hardening and says nothing about whether coolwsd degraded its
own jail (that is what `DECLARATIVE_JAIL` is for).
  </action>

  <what-built>
    `coolwsd` running under the declaratively-applied exemption set, with the exploratory
    drop-in removed, answering `/hosting/discovery` from inside the distro. What has not yet
    been proven is the Windows-to-WSL2 hop, which is D-13's actual bar.
  </what-built>

  <how-to-verify>
    1. First confirm `run.log` says `DECLARATIVE_REACH_GUEST=ok`. If it does not, stop — a
       Windows-side failure tells you nothing while the service is not answering in-guest.
    2. **On the Windows host, OUTSIDE WSL** (PowerShell or cmd, not Git Bash's guest shell):
       `curl.exe -sf http://127.0.0.1:9980/hosting/discovery`
       Expect exit code 0 and an XML capabilities document. Record the result in `run.log` as
       `WINDOWS_REACH=ok|fail`.
    3. If step 2 fails, apply RESEARCH Pitfall 1's discriminator BEFORE blaming hardening:
       - **Connection refused** usually means the bind address changed — check
         `settings.net.listen` and the `PrivateNetwork`/socket-activation concession from the
         ladder. Attribute `WINDOWS_REACH_CAUSE=hardening`.
       - **Timeout** usually means the WSL2 hop. Check `%USERPROFILE%\.wslconfig` for
         `[wsl2] localhostForwarding=false` and for mirrored networking mode, and check the
         Windows firewall. Attribute `WINDOWS_REACH_CAUSE=wsl-forwarding` and record it as
         **outside this spike's scope** — it is a WSL networking configuration finding, not part
         of the hardening exemption set, and must not be folded into it.
    4. **Browser check (D-13's stated bar, not automatable):** open `http://127.0.0.1:9980/` in
       a Windows browser. Confirm a Collabora surface renders — not a connection error, not a
       blank page. Note what you actually see; "the discovery XML rendered as text" is a
       different observation from "the Collabora welcome/editor surface loaded" and both are
       worth recording accurately.
    5. Confirm `wsl.exe -l -v` still lists `SourcererSpike`. Per CONTEXT's discretion default,
       leave it registered and warm for Phase 10 — do NOT run `wsl --unregister`. Record
       `DISTRO_FINAL_STATE=registered` in `run.log`.
    6. Confirm `git status --porcelain src src-tauri` prints nothing.
  </how-to-verify>
