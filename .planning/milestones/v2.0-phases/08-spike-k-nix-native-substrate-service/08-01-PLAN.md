<objective>
Stand up the spike 012 directory and its driver script, and establish the two environment
facts every later plan depends on: (a) the `SourcererSpike` distro is registered and warm on
a WSL build new enough to boot the 2605-line image, and (b) whether unprivileged user
namespaces actually work inside NixOS-WSL 2605.7.2.

Purpose: RESEARCH Open Question 2 is a pre-flight blocker, not a footnote. `coolwsd`'s entire
jailing path depends on unprivileged `unshare(CLONE_NEWUSER|CLONE_NEWNS)`. If that is
unavailable at the kernel/sysctl level, every subsequent hardening rung will show a degraded
jail for a reason that has nothing to do with systemd hardening — and the spike's evidence
value collapses unless the two causes were separated up front. STATE.md also carries an open
blocker: the local `nixos.wsl` image was deleted 2026-08-03 and `dist/` is gitignored, so the
distro's registration state is unconfirmed.

Output: `.planning/spikes/012-nix-native-substrate-service/run.sh` with its header, helpers,
leg selector, WSL-version gate, conditional re-import leg, and userns pre-flight — plus the
`run.log` capture proving those legs actually ran on the Windows host.

Probe three things, in this order, and record all three verbatim even when they disagree:

1. `sysctl -n kernel.unprivileged_userns_clone` via `guest_root`. Treat a non-zero exit or a
   `cannot stat` error as an expected outcome, not a failure: `kernel.unprivileged_userns_clone`
   is a Debian/Ubuntu/Arch downstream patch, not a mainline sysctl, and Microsoft's WSL2 kernel
   is built from mainline — its absence means this knob is not the gate, it does not mean
   namespaces are blocked. Record the literal result as `userns_clone_sysctl=<value|absent>`.
   RESEARCH names this sysctl by name in Open Question 2; recording that it does not exist on
   this kernel is itself a correction worth carrying to Phase 15.

   `max_user_namespaces=<n>`. A value of `0` means unprivileged userns are administratively
   disabled.
3. The functional probe, which is the only definitive answer: run
   `unshare --user --map-root-user -- id -u` via `guest` (UNPRIVILEGED — as the default `nixos`
   user, NOT `guest_root`; running it as root proves nothing about the unprivileged path
   coolwsd actually takes). Expect stdout `0` and exit 0 when unprivileged user namespaces work.
   Also run `unshare --user --mount --map-root-user -- true` to confirm the `CLONE_NEWUSER|CLONE_NEWNS`
   pair specifically — that is the exact combination `Kit.cpp` issues.
