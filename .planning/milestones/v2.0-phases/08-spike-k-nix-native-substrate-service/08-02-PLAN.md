<objective>
Bring `services.collabora-online` up inside the substrate in its stock, unhardened form, and
take the three control measurements the rest of the phase depends on: that the closure
substitutes rather than builds (SC-1), that the shipped module carries zero hardening
(RESEARCH finding 1), and what `coolwsd`'s jail state looks like when nothing is restricting it.

control. RESEARCH Pitfall 2 is that `coolwsd` logs
`"Security warning: running without chroot jails is insecure"` and keeps serving jail-less —
so if the stock service is ALREADY degraded (for example because plan 01 recorded
`USERNS_OK=no`), then no rung of the ladder can ever demonstrate a jail regression, and that
must be known and written down before rung 0 rather than discovered halfway up.

the resolved package provenance recorded in `run.log`.

recordable finding about D-12's "nothing compiles" premise, and RESEARCH flags an unreachable

rebuild.

probe helpers plan 03's `rung()` will call. Define the helpers at file scope (next to
`guest`/`guest_root`), not inside `leg_stock`, so plan 03 reuses them rather than duplicating
the grep patterns.

Helper `jail_state <since>`: greps `journalctl -u coolwsd -u coolwsd-systemplate-setup --since "<since>" --no-pager`
inside the guest and echoes exactly one of `ok` or `degraded`, plus the matched line as
evidence. Verdict rules:
  - `degraded` if the output contains the literal
    `running without chroot jails is insecure` (the `LOG_WRN` from `Kit.cpp` — this is
    coolwsd choosing to keep serving with no jail at all)
  - `ok` only if that string is ABSENT **and** a positive jail marker is present: a line
    containing `chroot(` (the `LOG_INF` coolwsd emits when it actually chroots inside its new
    namespace)
  - `unknown` if neither marker appears — never silently promote `unknown` to `ok`
Also capture, into the same evidence string, any of `SIGSYS`, `Seccomp`, `Operation not permitted`,
`Failed at step`, or `Permission denied` found in the same window. Those are the systemd-side
signatures the ladder needs verbatim; per RESEARCH's anti-patterns, "it didn't work" is not a
recordable reason, the log line is.

Helper `reach_state`: runs `curl -sf "$DISCOVERY"` through `guest` (unprivileged, in-guest —
NOT from Windows; Windows-side reachability is plan 04, and testing it here would fold WSL
localhost-forwarding failures into hardening findings per RESEARCH Pitfall 1). Echo `ok` when
the exit code is 0 and the body's first bytes are `<?xml`, otherwise `fail`. Use
`/hosting/discovery` rather than `/` — a bare TCP connect does not distinguish "coolwsd answered"
from "something else is listening".

The control measurement itself, run in this order and all recorded:
1. `systemctl is-active coolwsd` and `systemctl is-active coolwsd-systemplate-setup` via
   `guest_root` -> log `STOCK_ACTIVE=<value>`.
2. `systemctl show coolwsd -p User -p DynamicUser -p StateDirectory -p ProtectSystem -p ProtectHome
   -p NoNewPrivileges -p CapabilityBoundingSet -p RestrictNamespaces -p SystemCallFilter
   -p PrivateNetwork -p PrivateDevices -p MemoryMax -p CPUQuota -p TasksMax` via `guest_root`.
   Log the whole block verbatim under a `stock serviceConfig introspection` step. This is the
   evidence for RESEARCH finding 1 — that the nixpkgs module ships zero hardening — and it is
   also the "before" column Phase 15's compiler is written against. Expect `User=cool`,
   `DynamicUser=no`, `ProtectSystem=` empty, `CapabilityBoundingSet=` showing the full default
   set, and `RestrictNamespaces=` unset.
3. `jail_state "10 min ago"` -> log `STOCK_JAIL=<ok|degraded|unknown>` and
   `STOCK_JAIL_EVIDENCE=<matched line>`.
4. `reach_state` -> log `STOCK_REACH=<ok|fail>`.

Then emit the interpretation banner, which is the whole point of this leg:
  - `STOCK_JAIL=ok` -> the ladder has a real control; any rung that flips to `degraded` is a
    genuine hardening-caused regression.
  - `STOCK_JAIL=degraded` -> print an explicit warning that no rung can demonstrate a jail
    regression, cross-reference the `USERNS_OK` value from plan 01, and state that the phase
    verdict will carry that caveat. If `USERNS_OK=no` this is the expected, consistent outcome
    and confirms a WSL2 kernel gap rather than a hardening finding.
  - `STOCK_JAIL=unknown` -> print that the jail markers were not found at all and that the
    ladder's jail column will read `unknown` until a marker appears; do not proceed as if it
    were `ok`.
Do not abort in any branch.
  </action>
