<objective>
Apply the complete §7 hardening baseline to `coolwsd`, let it fail, then relax exactly one
directive per rung until a named stop condition fires — recording for every rung the directive
changed, the verbatim failure signature, the concession, and the reason.

Purpose: this is D-10 and it is the deliverable. The output is not a working service; it is the
exemption set plus its evidence, which Phase 15's manifest-to-unit compiler is written against
and Phase 19's `systemd-analyze security` audit cites. A green checkmark with no trail is a
failure of this phase even if `curl` returns 200.

Two correctness properties dominate everything else here:
1. **A rung never passes on reachability alone.** `coolwsd` logs
   `"Security warning: running without chroot jails is insecure"` and keeps serving with no
   jail. Every verdict cross-checks `jail_state` against plan 02's `STOCK_JAIL` control.
2. **The ladder has an unknown rung count.** It is a bounded, resumable loop with a named stop
   condition, not N hardcoded steps. Exhausting the timebox and recording the concessions
   reached is a pass (CONTEXT "Claude's Discretion", final bullet).

Output: `leg_ladder` filled into `run.sh`, `rungs.tsv` with one row per rung, and `run.log`
carrying the verbatim journal excerpt behind every row.
</objective>
